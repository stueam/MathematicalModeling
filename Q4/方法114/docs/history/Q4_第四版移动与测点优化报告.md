## 如何处理用户提出的思路

### 第二测点：把距离和后续清除一起计费

复核了本地第二问 README、V6 refinement，以及 Git 中的远端 B2 `flexible_b3.py`。第二问的区域半径/直径目标不能直接等同于 Q4 的完整任务时间。

对候选第二测点 q，现在比较：

```
当前位置到 q 的距离 / 5
+ 测量 5 秒 + 实际切频代理
+ 对 near、direction、no_signal 各反馈分支的后续完成费用求期望
+ 其他任务的剩余路线费用代理
```

局部完成费用含 q 到条件后验中心的距离、尝试清除、失败后的恢复及剩余位置分散程度。这样将“检测点1→检测点2”和“检测点2→目标中心”放在统一的秒单位下；没有只优化第二问的定位半径，也没有把无信号分支的剩余工作设为零。

在原候选之外，增加目标附近不同侧移距离、沿首次示向接近的候选、附近其他目标点、两目标中点、路线投影和邻近搜索站。先粗评，再精评前三个新候选，保留原有候选。正常清除与有限后备不变。费用期望仍是位置求积与局部代理，不是完整任务的精确最优期望。

代码：[q4/sector.py](q4/sector.py) 的 `ProbePolicy`、`movement_choices` 和 `probe`。

### 外侧点布局：原点 + 七个内环点 + 十四个外环点

当前骨架共 22 点：内环半径 975 m，外环半径 `1805/cos(pi/14)`。额外的 5 m 用于包含现有几何内核的源域外包；不能只按真实 1800 m 圆检查后忽略外包余量。

初始化使用完整三点凸包与 1000 m 内包圆的排除证书核验全域。外侧点提供布局结构，近邻目标参与共同生成第二测点；访问顺序仍由联合路线决定。计划删站或移站同样重新核验证书，假想阴性证据不写入实际状态。

螺旋也做了几何搜索：本批满足完整覆盖的离散螺旋候选路线约 25.6～30.2 km；可行双环参考路线约 17.6～17.9 km。这些只是有限候选的几何路线比较，不是螺旋或覆盖问题的全局最优证明。因此本轮采用双环作为完整补盲骨架，原 49 点网格作为有限后备。

### 不固定“做完这个分区才走”

实际实现并比较了硬性分区处理。它导致已知源与搜索站之间重复往返，因此当前默认不锁定分区。第二测点可以利用邻近目标和沿途站，但任务顺序交给联合路线；最多 16 个固定任务节点时继续用精确 Held–Karp。

## 距离 350 还差什么

独立新图平均仍差 **121.47 s/src**。平均最后一次成功清除后的证明工作已从 950.56 秒降至 398.27 秒；整局移动仍为 21278.82 m。

按真实源数进行事后评价：10 源的三局平均 588.19 s/src，15 源的三局为 381.21，16 源的一局为 357.29。源总数只能由评价器使用，不能作为在线策略的已知条件。后续重点是进一步合并源的定位路线与完整补盲路线，尤其减少少源地图的证明成本；保留完成约束继续优化，不能把达到 350 的部分场景当作任务完成。

## 运行

在本目录执行：

```bash
python run.py local --policy probes --seed 0
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python run.py benchmark \
  --seed 800 --rounds 16 --compare mobile probes --workers 16
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python run.py validate \
  --compare mobile probes --workers 16
```

本机依赖通过 `PYTHONPATH=/tmp/mathmodel_q4_deps` 使用。演练适配器支持显式 `--policy probes`，仍需 `--connect`，默认策略仍为旧 `mobile`。此报告不包含新版官方成绩。
