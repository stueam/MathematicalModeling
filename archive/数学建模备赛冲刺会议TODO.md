# 数学建模备赛冲刺会议 TODO

> 适用范围：全国大学生数学建模竞赛 A/B 题；剩余时间按 18 天有效训练 + 1 天机动安排。  
> 本次会议目标：不做泛泛讨论，在会内确定分工、训练题、交付物、截止时间和验收标准。

## 一、今天会议结束前必须定下来的 8 件事

- [ ] 明确三人的主责角色与副责角色：建模 M、编程 C、写作与验证 W。
- [ ] 每人说明已有能力、明显短板、可投入时间及不可用时段。
- [ ] 共同确认：只准备 A/B 题，不按题号预判题型，正式比赛先比较结构再选题。
- [ ] 确定知识补齐清单，并为每项指定“主讲人、学习人、验收日”。
- [ ] 确定第一轮精读真题、第二轮限时训练题和最终全真模拟题。
- [ ] 统一代码、文档、图片、实验记录和最终结果的目录与命名规则。
- [ ] 确定每天固定同步时间，以及阶段门未通过时的降级方案。
- [ ] 当场创建任务表，每项任务必须有负责人、截止时间、交付物和复核人。

会议结束的最低产出：一张分工表、一张能力矩阵、一份 18 天日程、三道训练题及负责人、下一次同步时间。

## 二、建议会议流程（45–60 分钟）

### 0–5 分钟：对齐目标

统一目标不是“学完所有算法”，而是形成一条三人能共同完成的比赛链条：

> 读懂题目 → 抽象结构 → 做出正确基线 → 选择匹配算法 → 得到可复现结果 → 完成多层验证 → 写成评委易核验的论文。

共同确认四条原则：

1. 优先保证正确、完整、可复现，再追求高级模型。
2. 每个复杂模型必须保留简单基线，增强模型要证明增量价值。
3. 每个核心公式和核心程序必须由第二个人复核。
4. 训练不能只“看懂”，必须留下代码、图表、写作段落或复盘表。

### 5–15 分钟：能力盘点

每人用 2 分钟回答：

- 我最有把握解决哪类任务？
- 我最可能拖慢团队的环节是什么？
- 我能独立完成的工具/算法有哪些？
- 比赛时我愿意承担什么主责？能为谁做副责？

按 0–3 分现场填写：0 未接触；1 能理解；2 能独立使用；3 能讲解、排错并复核他人。

| 能力 | 队员 1 | 队员 2 | 队员 3 | 主讲/负责人 |
|---|---:|---:|---:|---|
| 题意拆解、变量与约束定义 |  |  |  |  |
| 力学/几何/微分方程与数值计算 |  |  |  |  |
| 统计、拟合、误差与不确定性 |  |  |  |  |
| 优化、调度、动态规划/整数规划 |  |  |  |  |
| Python/MATLAB 数据处理与绘图 |  |  |  |  |
| 算法实现、调试、性能与复现 |  |  |  |  |
| 论文架构、公式、图表与排版 |  |  |  |  |
| 验证、敏感性分析与红队检查 |  |  |  |  |

### 15–25 分钟：确定主责与互备

建议采用以下角色，但不允许形成“只有一个人懂”的孤岛。

| 角色 | 主责 | 必须交付 | 副责/复核 |
|---|---|---|---|
| M：建模与数学 | 抽象、假设、核心方程、结构降维、算法依据 | 需求表、结构图、变量表、模型推导、情形树 | 复核程序是否忠实实现模型 |
| C：代码与数据 | 数据清洗、基线与主算法、实验管理、结果生成 | 可运行主入口、配置、日志、图表、结果文件 | 能解释核心公式并检查数值合理性 |
| W：写作与验证 | 论文骨架、逐问闭环、图表表达、验证矩阵、格式 | 主稿、摘要、验证报告、数字一致性清单 | 能独立复算至少三个核心结果 |

现场填写：

- M 主责：________；副责：________
- C 主责：________；副责：________
- W 主责：________；副责：________
- 总协调/版本冻结：________

角色不是工作量的三等分。正式训练中每 3–4 小时交换信息，任何阻塞超过 30 分钟必须显式求助。

### 25–40 分钟：确定学习与真题任务

知识学习遵循“最低理论 + 可运行例题 + 本题使用判断 + 常见失败”四件套。禁止只收藏课程或只整理算法定义。

优先级分为三层：

- P0 共用底座：需求拆解、量纲/单位、拟合与残差、约束优化、敏感性分析、绘图、论文结构、代码复现。
- P1 连续机理/几何/反演：向量几何、受力与守恒、ODE 数值法、非线性方程、最小二乘、离散收敛、参数可识别性。
- P1 数据/决策/随机：回归与验证、动态规划、整数规划、状态转移、蒙特卡洛、置信区间、随机算法重复试验。
- P2 按题触发：PDE、图论、启发式算法、多目标优化、机器学习等；不提前无差别铺开。

每项知识的验收格式：

### 40–55 分钟：锁定 18 天计划

现场给每个阶段指定负责人，确认每天可以投入的真实时长。若剩余天数少于 18 天，优先压缩知识补齐，不压缩限时模拟和复盘。

### 55–60 分钟：复述与承诺

每人依次复述：

1. 我今晚/明天要交什么；
2. 文件放在哪里；
3. 谁来验收；
4. 遇到什么情况必须求助或放弃当前路线。

## 三、18 天备赛推进表

### D-18：团队基线与环境统一

- [ ] 完成能力矩阵和主副责分配。
- [ ] 三人分别阅读一套 A/B 题，各交一页需求表，不先讨论。
- [ ] 统一 Python/MATLAB 环境、字体、求解器及版本。
- [ ] 建立共用目录、代码入口和实验记录模板。
- [ ] 选出一篇优秀论文，三人分别标注其“抽象、算法、验证、写法”。

验收：任何人能在新环境运行示例程序并生成同一张图；三人的题意遗漏能够被汇总发现。

### D-17～D-15：分工学习 + 小题实操

- [ ] M 主讲连续机理/几何建模底座，完成一个小型机理或几何例题。
- [ ] C 主讲数据处理、求解器、实验配置和可复现绘图。
- [ ] W 主讲需求表、论文逐问闭环、摘要和验证矩阵。
- [ ] 每人学习另外两人的主讲内容，并完成一次交叉提问。
- [ ] 建立共用代码模板：数据读取、配置、日志、随机种子、绘图、结果导出。

验收：每个知识点都有“何时用、何时不用、最容易错什么”；代码不是零散 Notebook 单元。

### D-14～D-12：第一轮真题精读（不追求限时）

选一套包含连续机理/几何指纹的题，以及一套包含数据/决策指纹的题。建议从已有 2016–2025 A/B 题库中选择，避免只练同一类型。

每道题必须完成：

- [ ] 每问的输入—状态—决策—约束—输出表。
- [ ] 一张因果图、几何图或状态图。
- [ ] 最小可行模型和一个简单基线。
- [ ] 情形树、约束账本、假设账本、验证计划。
- [ ] 主算法选择理由及放弃条件。
- [ ] 对照优秀论文，只在自己完成路线后阅读。
- [ ] 写 1 页复盘：我们漏了什么？优秀论文真正多做了什么？哪些做法不值得照搬？

验收：不是“看完论文”，而是能在不看原文时讲清模型链、证据链和一个真实创新点。

### D-11～D-9：第一次 24 小时压缩训练

目标是打通全流程，不要求达到最终比赛质量。

- 前 60–90 分钟：三人独立读 A/B，使用评分卡选题。
- 第 2–6 小时：完成需求表、骨架、基线和第一张验证图。
- 第 6–14 小时：完成全部题问的可行版，最多增加一个增强点。
- 第 14–20 小时：补情形、敏感性和独立复算，冻结结果。
- 第 20–24 小时：完成摘要、正文骨架、核心图表和提交检查。

验收：形成可打开的 PDF 主稿、可运行代码和完整结果文件；每问都有“模型—结果—验证”闭环。

### D-8：集中复盘与补洞

- [ ] 按题目每个动词检查需求覆盖率。
- [ ] 找出最慢的三个环节及根因：知识、协作、代码还是写作。
- [ ] 由非主导者红队检查边界、退化、不可行和极端情况。
- [ ] 删除没有增量价值的复杂模型。
- [ ] 每人确定接下来只补一个高收益短板。

验收：输出“问题—证据—修改—负责人—截止时间”表，不用“配合不好”“时间不够”等模糊表述。

### D-7～D-6：针对性补强

- [ ] 重做第一次训练中最薄弱的一问。
- [ ] 给核心算法增加基线、重复试验、收敛曲线或运行时间记录。
- [ ] 给核心模型增加单位、守恒、边界、扰动中的至少三类验证。
- [ ] 练习从最终数值提炼阈值、单调区间、主导因素或策略规律。
- [ ] 完成一版摘要模板和论文目录模板。

验收：增强模型必须量化说明比基线好在哪里；无法证明时降级表述，不写“全局最优”。

### D-5～D-3：第二次全真模拟（按正式赛程）

完整执行正式比赛 Pipeline：

- [ ] 90 分钟内完成双题独立阅读、评分与选题。
- [ ] 4–6 小时内打通端到端基线。
- [ ] 中期完成全部题问的可行版，不把最后一问留成口头设想。
- [ ] 增强点最多两个，必须有量化增益。
- [ ] 设置结果冻结时间，冻结后只修 bug。
- [ ] 交叉审稿：M 查数学，C 从主入口复跑，W 按评委视角查叙事和需求覆盖。
- [ ] 最后阶段只做格式和提交安全，不再结构性改模。

验收：一名未主导该段的人能在 5 分钟内说清输入、公式、输出、验证；核心数字在摘要、正文、表格和附件中一致。

### D-2：全真复盘与模板冻结

- [ ] 冻结可靠的代码模板、绘图模板、论文骨架和检查表。
- [ ] 整理常用函数，但删除未经测试的“大而全算法库”。
- [ ] 形成 A/B 选题评分卡和团队风险清单。
- [ ] 每人写一张比赛首日行动卡。
- [ ] 确认比赛用品、软件许可、离线资料及备份方式。

### D-1：轻量热身与休息

- [ ] 只做 1–2 小时结构识别和口头推演，不再学习大型新算法。
- [ ] 检查环境、模板、资料和作息。
- [ ] 明确比赛当天集合时间与第一次同步节点。
- [ ] 保证睡眠，避免赛前透支。

### 机动日

仅用于补因故中断的模拟或修复环境问题，不用于无限扩展知识清单。

## 四、真题阅读的统一方法

每篇题目和优秀论文按同一张卡片记录，避免三个人只分享“这篇用了什么算法”。

### 读题卡

1. 每问要求的动作是什么：计算、预测、评价、设计、证明还是给策略？
2. 输入、状态、决策、约束、观测和输出分别是什么？
3. 题目属于连续机理/几何/反演，还是数据/决策/随机，或是二者混合？
4. 哪个结构可能降维：守恒、对称、单调、尺度、可分性、关键节点？
5. 4–6 小时内能否得到一个正确基线？
6. 最容易漏掉的边界、退化、不可行或信息条件是什么？
7. 至少三种验证渠道是什么？

### 优秀论文蒸馏卡

1. 最关键的抽象是什么，而不是模型名称是什么？
2. 作者如何把复杂问题压缩到可计算规模？
3. 算法为什么匹配该结构？是否保留基线？
4. 作者考虑了哪些一般论文容易漏掉的情况？
5. 哪个验证最能反驳作者自己？
6. 哪张图/哪张表最降低评委核验成本？
7. 最值得迁移的一种写法是什么？
8. 哪些做法只是包装，不应模仿？

阅读顺序：先独立做题框架，再看摘要和目录，再看核心推导与验证，最后回到全文检查叙事。禁止一拿到题就照抄优秀论文路线。

## 五、每日协作制度

### 每日 10 分钟同步

每人只回答五项：

1. 已完成并可复核的交付物；
2. 当前阻塞及已尝试的方法；
3. 下一个可验收交付物和完成时间；
4. 是否触发当前路线的放弃条件；
5. 需要谁在什么时候复核。

### 文件与版本约定

- 题目和原始附件只读保存，不覆盖原文件。
- 一个主入口运行完整流程，禁止最终结果依赖手工复制。
- 所有随机算法记录随机种子、参数、重复次数和最好值历史。
- 图表由代码生成，标题写明变量、条件和单位。
- 建立 `results-frozen`；冻结后只有明确 bug 才能改变核心数字。
- 摘要、正文、表格和附件中的核心数字保持单一来源。

建议目录：

```text
team-project/
├─ problem/          # 题面与只读附件
├─ notes/            # 需求表、假设账本、情形树、复盘
├─ src/              # 可复用代码与主入口
├─ experiments/      # 配置、日志、临时结果
├─ figures/          # 由代码生成的图
├─ results-frozen/   # 冻结结果
└─ paper/            # 主稿、参考文献、最终 PDF
```

### 阻塞与降级规则

- 同一技术问题独立排查 30 分钟仍无进展，必须同步，不能静默消耗数小时。
- 高级算法 2 小时内未超过基线，先保住基线，再评估是否继续。
- 某一问短期无法完整解决时，先完成简化情形、明确适用边界并保留接口。
- 结论对合理扰动发生翻转时，改写为条件性结论并报告阈值。
- 不能证明全局最优时，写“当前搜索范围内的最好可行解/近似最优解”。

## 八、阶段验收底线

- [ ] 三人都能独立完成题意需求表和基本结构判断。
- [ ] 团队能在 90 分钟内完成 A/B 比较并给出可解释的选题依据。
- [ ] 能在 4–6 小时内打通一个端到端基线。
- [ ] 每问都有结果、验证和现实解释，不只给模型名或软件输出。
- [ ] 情形树与代码分支一致，硬约束逐条可核对。
- [ ] 核心结论至少通过内部一致性、边界/极端、扰动/敏感性三类验证。
- [ ] 任一核心模块至少两人能够解释、排错和接手。
- [ ] 主入口可复现最终图表与结果，正文和附件数字一致。
- [ ] 摘要能说明方法、关键结果、适用条件和可信度证据。

> 最后的判断标准：训练结束时，我们拥有的不是一堆看过的算法，而是一支能稳定完成“选题—建模—求解—验证—写作—提交”全流程的三人团队。
