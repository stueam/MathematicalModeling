## 3. 实现机制

### 3.1 联合任务节点

同一路线中同时放入：

- 已知源的定位/清除任务；
- 尚需实际扫描的覆盖站；
- 每个任务声明的必要后续扫描服务。

下一步可以先处理一个源，也可以先去顺路的覆盖站；收到反馈后重新生成候选。每次仍提交一个合法原子动作，同点批测逐条执行并响应near，不把计划当成已经完成的观测。

### 3.2 清除后的扫描服务必须真正执行

V3用预测路线停靠点评价未来覆盖，但机会扫描可能最后没有被执行。V4把“成功清除后，在当前点扫描仍有几何覆盖价值的未知频道”列为实际任务。

失败clear不直接触发成功清除服务；若已经确认16个频道存在，可依据总数上界省略其余频道搜索，但仍要完成这16个源的清除。频道覆盖记录完全独立。

这解释了测量次数增加：新版兑现了原先只是预测的覆盖工作，从而减少后期折返。

### 3.3 对未来清除点的覆盖预测留几何余量

对已知源c，当前代表位置为μ，完整保守区域P的最大顶点距离为

\[
\rho_c=\max_{v\in vertices(conv(P_c))}\|v-\mu_c\|.
\]

最终成功清除位置与真实源相距不超过20m，因此其到μ的距离不超过ρ+20。若届时实际扫描某未知频道，则其1000m接收盘至少覆盖

\[
B\bigl(\mu_c,[1000-\rho_c-20]_+\bigr),
\]

代码再用内包圆保留数值余量。ρ来自完整几何，不是90%可信区域。

用这些**条件性的未来覆盖**扣除尚未排除区域，求仍需补充的覆盖站。条件是未来真的成功清除并完成相应扫描；该预测从不写入实际Belief，也不参与实际done判定。

### 3.4 覆盖子集与路线联合比较

七站骨架各子集先检查能否覆盖完整的预测剩余区域。按便宜的插入绕行估计筛选最多3个不可删减的可行覆盖子集，再分别与已知源组成联合节点集合。

每个候选都计入本次移动、检测/清除代理、其他源的局部工作、扫描服务与剩余联合路线。V3的原动作保留并在同一个联合任务清单下重新计价，避免拿两种不同评分口径的数值直接比较。

接收半径、误差和未知源数量的贝叶斯模型继续沿用原实现。完整几何、计费和停止规则没有放宽。局部完成时间仍是启发式，未知反馈改变未来路线的价值没有被精确求解，不能把score当作精确的整局最优剩余时间。

### 3.5 更强的开放TSP与条件后缀

`open_routes.py`：

- 节点数≤12时使用子集动态规划，对固定坐标的开放TSP子问题精确求解；不添加返回原点的边。
- 更大规模使用4个初始点的最近邻、2-opt和单点重插入。
- 比较一个候选完成后，从其实际/预测完成位置重新优化剩余访问顺序，不机械沿用旧路线删掉该节点后的顺序。

这只是固定代表位置子问题的优化，不等于整个部分可观测任务精确最优。

### 3.6 纯几何缓存

多个测量候选共享相同的预测完成位置和剩余任务时，其几何后缀完全相同。缓存包含不可变节点坐标表、起点和剩余节点集合，返回路线副本，避免调用者污染缓存。

这不是模拟世界或策略完整后续成本缓存，不依赖真实源、绝对时间或随机反馈。缓存前后10张开发图的虚拟时间、移动距离和操作次数逐局一致。

该开发批次的平均实际循环时间从25.68s降至5.72s，但批次负载不同，不把该比值作为严格固定工作量加速比。

## 4. 对用户四项建议的处理

| 建议 | 本轮算法三实现 |
|---|---|
| 定位、清除、补盲同一路线 | 已实现联合节点、预测覆盖和实际扫描服务，实测有效 |
| 比较不同后续策略 | 用“先完成该源再走剩余路线”与“先沿路测量再继续联合路线”两种确定性代理做对照；不做世界rollout |
| 小批完整配对世界 | 这是算法二MC机制，本轮按用户确认仅改算法三；16进程用于独立本地案例，确定性决策用路线缓存控制成本 |
| 偏离基线复核 | 实现双分辨率确定性求积复核，作为可选实验；不称为独立随机样本置信检验 |

可选沿路探测 `bayes-joint-probe`：在近期任务点为附近已知频道生成测量动作，随后继续整个混合路线，不假设立即折回清除此源。

可选复核 `bayes-reviewed`：若相对V3动作多走>50m，而粗评分收益<30s，则用更细位置求积重新估计两动作的局部贝叶斯成本；细评分需有>3s收益才接受，否则采用V3动作。细求积复用同一几何任务表，是数值敏感性复核，不是统计保证。默认24×24与48×48，精细分辨率最高96。
