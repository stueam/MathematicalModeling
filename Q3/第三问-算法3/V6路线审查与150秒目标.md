# V6路线审查与150秒目标

2026-09-11。用户确认朋友的150秒/源是多局全清后的平均。本文复核本项目已有十轮官方软件问题3演练，不调用模拟器；尚无朋友的动作日志或同图对照。

十轮使用的是V5，119/119源清除，汇总243.27秒/源；V6只有本地试验，500～519留出集相对V5平均改善约0.96%。因此当前证据不支持V6已接近150秒/源。

## 费用与新的事后路线参照

十轮总费用28949.23秒，其中移动21443.23秒，占74.07%；每源移动180.20秒，非移动63.08秒。实际客户端平均2.94秒/局与上述虚拟任务耗时是不同指标。

新脚本 `audit_movement.py` 只读取已结束案例的公开动作。它用成功clear的提交坐标建立事后开放TSP，16点以内精确求解，不读真实源坐标或R，不向任何策略提供这些未来信息。

| 十轮按局平均 | 距离 |
|---|---:|
| 实际全部移动 | 10.722 km |
| 保持实际清除顺序，直接连接成功clear点 | 9.250 km |
| 事后知道全部成功clear点，精确重排开放TSP | 8.182 km |
| 进一步允许清除点变化的源访问路程下界 | 7.270 km |

实际路线与同序clear折线相差1.472km/局，包含搜索、测向和尾部移动，不能全部当作冗余。同序clear折线与事后TSP相差1.068km/局，说明访问顺序也有空间，但当时并不知道全部clear点。两项不能宣称为在线算法能实现的节省。

下界的构造：历史成功clear点q和任何另一成功清除同一源的点z，距离最多40m。把任意源访问路线中的z替换成q，首边最多增长40m，后续N−1条边各最多增长80m。因此：

`实际所需源访问距离 ≥ max(0, 事后clear点最短开放TSP − 40(2N−1) − 0.01)`。

额外减去0.01m作为数值余量。这个下界不计发现、定位和无源证明，可能远低于真实最优任务路程。

**保持现有非移动费用不变时，即便取上述很乐观的移动下界，十轮汇总仍至少185.27秒/源。** 若达到150秒/源，在该移动下界处非移动预算也只有27.81秒/源，实际可用预算可能更少。这是对这十张地图、现有非移动总费用的条件结论，不是150秒目标一般不可能。

所以路线必须优化，同时还要减少搜索测量。当前扫描总费用不是可以原样保留的固定常数。

## V6仍继承的结构问题

1. `joint.py::_score` 对同一源的各测量位置，先对反馈积分估计局部完成费用，后续TSP却统一从测量前的代表点 `points[c]` 出发。反馈改变完成位置、目标顺序和扫描服务的价值没有一起积分；测量的路线收益可能被错误排序。
2. `sectors.py::_coverage_tasks/_plans` 固定角扇区并合并各频道区域；一个清除停点必须独自保证覆盖整个任务才能承接。多个清除停点合起来足够覆盖时，仍可能保留专门测站。可保留完整几何约束，改成逐频道残余区域的联合覆盖与自适应任务。
3. `finish_cost/clear_finish_cost` 用“失败后一次补测”的11秒加平均纠偏距离估计恢复。它不是完整后续模拟，尤其对单方向长条区域和失败后的多次定位可能失准。
4. 混合路线计入已发现源及未知频道的扫描费用，没有把未发现源的未来定位清除路程完整展开。规划中的便宜扫描站不一定对应便宜的完整任务。

## 改革方向与验收

- 覆盖与源访问共同优化：对每个频道，用沿途多个可服务停点的保守接收区域取并集，仅为剩余几何安排额外测站。选择哪些频道在哪些停点测量，同时权衡额外路程与5/6秒测量费。所有覆盖证据只由实际反馈写入。
- 测量与后续路线共同评分：预测反馈后更新目标位置和剩余路线，纳入失败与无信号分支。先校准代理，再决定是否用完整配对rollout复核少量重要长移动。
- 连续优化实际服务点：测向点尽量插在原路线附近；已可靠定位源在合法20m清除范围内选择有利于进出路线的点。原点重测、低概率区域丢失和提前退出都不能成为“提速”来源。

每项保留可运行对照，先小批同图开发，再固定配置跑未使用种子和极值/相关误差。报告全清与证明完成比例、虚拟耗时、移动、测量、失败清除和实际计算时间。150秒是目标，不是承诺。
