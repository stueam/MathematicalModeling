# 第三问算法二：粒子信念与 POMCP-lite

完整原理、分组结果、三倍预算失败实验与下一版设计见 [方法二原理与结果说明](方法二原理与结果说明.md)。当前默认参数保持一倍；三倍配置在种子 20 同图实验中虚拟耗时增加 7.92%，实际计算为 5.11 倍。后续验证仅使用本地模拟。

实现依据本目录原始 Word 指导。原文和算法一源码保持不变。算法二使用 16 个 CPU 进程、每进程数值库单线程；控制器只接收公开观测，只有本地环境和评估器读取真值。

本地验证结果与限制见 [实现与验证报告](实现与验证报告.md)：最终配置 12 局全部清除；三张独立地图相对算法一快速策略/MC 的总虚拟时间分别减少 16.53%/11.92%，同时增加实际计算时间，压力场景有一局退步。

随后已完成官方软件的 **3 局问题3演练**，33/33 源清除，汇总 291.97 秒/源，没有启动正式测试。详见 [官方模拟器演练报告](官方模拟器演练报告.md)。WSL 下的演练专用入口为 `practice_windows.py --connect --rounds 3 --workers 16`，会在接口调用前核验演练界面。

## 运行

Python 3.10+，保留相邻的 `第三问-算法1/q3` 目录，它提供共用的物理、协议和保守几何内核。

```bash
cd 第三问-算法2
python -m pip install -r requirements.txt
python run.py local --workers 16 --seed 0
python run.py benchmark --workers 16 --seed 10 --rounds 5 \
  --compare algorithm1 algorithm1-mc macro-baseline pomcp
python -m pytest -q tests
python validate.py --workers 16
```

当前机器已有临时 Shapely 依赖时，可在命令前加 `PYTHONPATH=/tmp/mathmodel_q2_deps`；源码不依赖这个临时路径。

策略名称：`algorithm1` 是算法一当前 `MovementPolicy`；`algorithm1-mc` 是算法一 `mc-race`；`macro-baseline` 是算法二的宏动作启发式；`pomcp` 是算法二完整规划器。比较 MC 时，两边共用本次指定的进程数、候选上限、初始/最大世界数和单次预算，但候选集、后续策略与分配机制不同，不能解释成单独的粒子方法或 CPU 加速收益。

默认 3000 粒子/频道，粗评 16 世界/候选、6 个宏动作前缀；前 4 个候选精评 48 个新世界、8 个宏动作前缀；单次规划预算 5 秒。原算法一和宏动作基线均保留到精评。可以按指导提高预算：

```bash
python run.py local --workers 16 --coarse-worlds 48 --fine-worlds 192 \
  --horizon 6 --fine-horizon 8 --budget-s 15
```

世界数、深度是计算预算，不改变任何物理规则。对有截止时间的运行，只有完整配对批次参与选择；未完成批次丢弃并记录。不同硬件可能完成不同批次数，固定预算下的整局路线不一定相同；固定批次的单/多进程成本一致有测试覆盖。

## 三倍计算预算实验

`--compute-scale 3` 对以下八个计算参数整体乘 3，保留随机种子、16 个进程、工作先验、物理规则、完成判据和官方实际时限。它是独立实验配置，默认配置仍可用于对照。

| 参数 | 1 倍 | 3 倍 |
|---|---:|---:|
| 粒子/频道 | 3000 | 9000 |
| 粗评候选上限 | 12 | 36 |
| 粗评世界/候选 | 16 | 48 |
| 精评保留候选 | 4 | 12 |
| 精评新世界/候选 | 48 | 144 |
| 粗评前缀深度/宏动作 | 6 | 18 |
| 精评前缀深度/宏动作 | 8 | 24 |
| 单次规划预算/秒 | 5 | 15 |

```bash
# 相同隐藏地图、相同误差场，顺序运行 1 倍和 3 倍配置
python compare_compute.py --seed 20 --rounds 1 --workers 16

# 官方软件的问题3演练；仍拒绝正式测试界面
python practice_windows.py --connect --rounds 1 --workers 16 --compute-scale 3

# 单独跑本地三倍配置
python run.py local --seed 20 --workers 16 --compute-scale 3
```

候选和世界数同时增大后，单次完整两级评估的名义条数上限从 384 增为 3456（9 倍），实际可能受候选不足或时间预算限制。完整尾价值模式本来就会模拟到任务终局，因此前缀从 6/8 增到 18/24 不增加完整模拟所看的未来。应结合已完成批次、被丢弃批次、实际候选数与任务成绩判断效果，不能只比较配置中的数字。

## 与指导的对应

| 指导要求 | 实现 |
|---|---|
| `(x,y,R,w)` 粒子、ESS、更新和重采样 | `pomcp/belief.py`：固定 R 粒子，低 ESS 时从完整历史条件后验重新生成；不使用可能越过约束的任意抖动 |
| 无源必须严格证明 | 复用 `q3/core.py` 外包可行域与内包排除圆；逐频道记录；16 个不同频道已确认存在时使用数量上界 |
| 总数 10–16 的相容世界 | `pomcp/world_sampler.py`：数量约束下的联合存在性抽样，半径和所有历史测量相容 |
| 独立生成模型 | `pomcp/generative_model.py` 只组合 `q3/simulator.py` 的真实原子动作，不调用 HTTP |
| clear / probe / shared / blind / route | `pomcp/action_gen.py`；clear 候选不要求概率先达到 0.95；清除点最大化有限候选上的 20 米粒子覆盖概率 |
| Open-TSP 与动态插入 | `pomcp/routing.py`：开放路线、最便宜插入和 2-opt；不要求回原点 |
| 两级筛选、统一时间目标 | `pomcp/planner.py`：几何候选剪枝、共同世界配对、分阶段精评，只比较完整任务虚拟时间 |
| 势函数和尾价值 | `pomcp/heuristic.py`、`pomcp/rollout.py`，详见下节 |
| 有限完成后备 | 重复定位/失败清除达到阈值后，使用完整可行域的有限网格覆盖；预算预留阶段执行算法一可靠策略 |
| 真实闭环与日志 | `run.py`：批内串行、响应后更新、重新规划、日志持久化、严格 exit |

UNKNOWN 不依赖粒子消失或低概率退出。DETECTED/LOCATED 的概率标签只用于决策；是否完成由保守几何和成功反馈决定。`near` 为 ≤5 米；测量方向误差包含两位小数舍入，支持 ±1.005°；失败 clear 只排除其 20 米圆盘，绝不删除已发现频道。各处位置坐标直接提交，允许在目标域外测量。

## 为什么默认采用完整后续尾价值

实现保留指导中的 `H=T_route+T_clear+T_localize+T_search` 几何尾价值，以及 `Phi=-H, gamma=1` 的时间目标。但开发实验发现它明显高估前期未发现源的剩余费用，诱使短程规划提前绕行。独立公开历史快照审计也发现该偏差，所以没有把较差的短程版本作为默认策略。

默认 `--tail completion`：在有限前缀后，继续让只看模拟反馈的宏动作策略在同一抽样世界中完成全部剩余工作；这相当于对 `H_pi(b_leaf)` 使用一条条件后续样本。它没有改变原始奖励 `-Δt`，没有省略任何费用，且可直接利用终局 `H=0` 的望远镜消去性质。全程仍只在根节点比较动作，不建立 PO-UCT 历史树，不嵌套 MC，也不让策略读取抽样世界真坐标。

`--tail geometric` 保留作短程版本消融与研究，当前不推荐用于最终任务。其末尾估计不是最优成本或可证明下界。独立验证命令：

```bash
python audit_tail.py results/某批次/0-pomcp/actions.jsonl --workers 16 --worlds 32
```

## 规则与计费

所有真实/模拟动作共用同一个计费内核：移动 `距离/5`，测量 5 秒，测量切换频道另加 1 秒，清除成功 5 秒、失败 3 秒。clear 不切换接收频道。同源 R 整局固定，同频道同坐标误差固定，重测不会刷新误差；rollout 从历史中恢复已知示向度。

位置均匀、R 均匀、未知频道先验 0.65、不同位置误差独立均匀，均为工作先验，题设只规定范围。压力测试另外使用边界源、R 极值、±1° 极值误差和空间相关误差；保守几何不依赖这些先验成立。

粒子数、有限提议点、Open-TSP 和 cheap screening 都是数值近似/启发式，不声称连续后验、连续清除点或全局路线的精确最优。它们不能替代无源证明。任意有限现实截止时间下不承诺无条件完成；耗时或数值异常必须在 summary 中报告为未完成，不能记成成功或提前 exit。

## 输出与正式接口

每次运行新建 `results/时间戳/`，保存配置、源码 SHA-256、配对汇总和每局动作、逐次 belief、候选成本矩阵、有效世界数、完整 rollout 条数/步数、丢弃批次与回退原因。虚拟任务时间与实际计算时间分开报告。测量、切换、失败清除、移动距离和发现至清除耗时均可从日志核验。

程序默认只运行本地模拟。用户明确授权且官方界面已就绪时才连接：

```bash
python run.py official --connect --robot-id 参赛队号 --workers 16
```

串行 HTTP、同 ID 同内容重试及响应校验复用算法一适配器。使用 `/enter` 返回的实际剩余现实时间和虚拟上限；只有严格完成才发 `/exit`；不确定请求结果后不会发送替代动作或 exit。本地测试不等于官方演练，官方加密日志须由官方软件原样导出。
