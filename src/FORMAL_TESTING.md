# Q3 / Q4 正式单局运行说明

正式入口是各目录的 `start_formal.py`。Q3 固定使用论文的 `bayes-fast`，Q4 固定使用论文的 S21＋probes；两者均调用各自唯一的 `Policy`，参数与本地和演练入口一致。

## 正式与演练分开

| 用途 | Q3 | Q4 |
| --- | --- | --- |
| 演练 | 原 `practice_windows.py` | 原 `start_s21.py --connect --rounds 1` |
| 正式 | `start_formal.py --connect --case 本局编码` | `start_formal.py --connect --case 本局编码` |

正式入口不会点击开始测试、确认、中止或返回按钮，不创建下一局，也没有批量运行参数。只接入用户已在模拟器中启动、倒计时结束且显示“尚未进入”的当前正式案例。题号、正式标题、案例编码和接口端口必须一致。账号从可见界面读取，不必写进代码。

## 操作顺序

1. 使用完整目录和已验证的 Python 环境。在相应 `src/Q3` 或 `src/Q4` 目录运行 `python -m pip install -r requirements.txt`；准备阶段完成安装，不要等正式倒计时开始才安装依赖。
2. 停止其他正在运行的机器狗客户端和批量演练脚本。两个新的正式入口有同端口互斥锁，但不能阻止旧演练脚本或第三方客户端连接。保持官方模拟器登录、联网和可见。
3. 在相应目录先运行默认检查：

   ```powershell
   python -X utf8 start_formal.py
   ```

   该命令不连接 HTTP。当前不是就绪正式页时返回 `ready: false` 是正常保护，不会启动测试；读取界面可能将模拟器窗口置于前台。

4. **由队员在官方模拟器中启动并确认对应题号的正式测试**。正式机会在模拟器启动成功时占用，不是运行检查命令时占用。等待 5 秒倒计时结束，核对题号、案例编码及“尚未进入”。
5. 在对应目录运行以下命令，替换示例编码为本局实际编码：

   ```powershell
   python -X utf8 start_formal.py --connect --case XXXX-XXXX-XXXX-XXXX
   ```

   默认接口是 `127.0.0.1:2026`；仅当界面显示不同端口时显式传入 `--port`。`--output E:/FormalRecords/Q3` 可指定日志父目录，每次创建新的案例子目录，不覆盖旧记录。
6. 等待本局结束。正常退出后会打印成功清除数和“总虚拟时间÷成功清除数”。随后在官方界面核对测试结束、正式日志上传状态，导出原始加密日志，并保存结果页或日志列表截图。

## 记录与指标

每局目录默认是当前算法目录下 `results/formal/案例编码-时间戳/`。

| 文件 | 内容 |
| --- | --- |
| `config.json`、`policy.json` | 代码 SHA-256、Python、题号、案例、策略类型和配置 |
| `http-attempts.jsonl` | 每次发送前即落盘，记录同 ID 重试、HTTP 原始响应和异常；队号隐去 |
| `actions.jsonl`、`decisions.jsonl` | 已接受动作、响应、规划耗时与原策略决策记录 |
| `enter.json`、`exit.json` | 官方接口的进入预算和退出响应；失败时可能没有退出文件 |
| `summary.json`、`http-log.json` | 结果、成本核验、结束原因和汇总通信记录 |
| `ui-before.json`、`ui-after.json` | 运行前后可见界面证据；无法读取结束页会记录警告 |

正式测试不公开真实源总数及类型数量，因此 `source_count`、`clearance_fraction`、`official_all_cleared_verified` 保持空值。`algorithm_complete` 只表示原算法依据反馈达到自身停止条件，不能替代官方对全部源的最终核验。

`status=completed` 表示算法正常结束且 `/exit` 已确认；`average_per_cleared_s` 是总虚拟时间除以成功清除的不同频道数。零清除时不计算平均数。`incomplete` 表示因预算或动作上限提前退出；即使有平均数也不能作为完整任务成绩。`stopped` 表示出现异常，平均成绩留空，仅保留 `last_known_average_per_cleared_s` 等已知过程数据。

`server_program_time_s` 来自进入与退出响应的时间戳差；`client_elapsed_s` 是本机端到端耗时。二者均不是“总虚拟时间”。本地 JSON 日志不等于官方 `.jlog` 加密行为日志：**仍需从模拟器导出正式日志，保留原文件名并核对上传状态**。入口不自动导出或代报上传成功。

## 异常处理

- 倒计时、错误题号、演练页面、案例不匹配或已进入状态都会阻止接入。不要为了绕过检查而删除标题校验。
- 网络超时仅由原 HTTP 客户端用完全相同的请求字节和 `request_id` 有限重试；重试仍失败时停止，不另发新的替代动作，也不在结果不确定时补发退出。
- 已知结果下接近现实时间上限时，停止规划并尝试正常退出；已经到期则不再发送请求。原算法动作上限 Q3 为 4000、Q4 为 6000。
- 出现异常时保留模拟器和当前记录，检查具体错误及官方界面。不要盲目重跑已进入的案例；此入口不支持从中断状态恢复。是否手动中止由队员根据当时状态决定，中止也占用正式机会。
- Windows 短暂文件占用仅重试本地日志重命名；不会因此重发机器狗动作。持续磁盘错误会停止运行，已写入的逐条日志可用于追溯。

## 验证边界

新增入口通过本地模拟 HTTP 与固定种子场景核验，不启动官方正式测试。测试覆盖错误模式拒绝连接、单局限制、日志、超时重试、异常停止、计时与原算法动作序列一致性。

复核命令（在各自算法目录运行）：

```powershell
python -m pytest -q
```

正式页面的实际端到端接入尚需在队员授权启动的正式案例中观察。当前验证不冒充已完成正式实测。
